# 综合考核系统 · 自编题 / 军事技能训练 / 学生手册 / 安全知识

一个带**考场管控**的在线考核系统：随机抽题组卷、自动判分、错题回溯，
考生用自己设备答题，成绩**自动上传云端**，教师在**教师端看板**上实时汇总全班成绩；
考核期间检测到违规行为会**立即交卷、上报教师端并在名单中标红**。

- 学生端：`index.html`
- 教师端：`teacher.html`

## 抽题规则（全卷 50 题）

| 题型 | 题量 |
| --- | --- |
| 单选 | **30 题** |
| 多选 | **20 题** |
| **合计** | **50 题** |

- **抽取方式：纯随机抽取，不按题库分配名额。** 三个题库（军事技能训练理论 320 题、学生手册 120 题、
  安全知识 120 题）合并成一个池子，从池子里随机抽 30 道单选 + 20 道多选。
- 因为军事技能训练理论题库最大（占总题量的 57%），**它自然会被抽到最多**；
  三个题库也都会稳定地有题被抽到（每套卷至少各 1 题，实际通常各 5~18 题）。
- 每题 **2 分**，全卷 **100 分**，**60 分及格**，限时 **35 分钟**。
- 多选题**少选、多选、错选均不得分**（需与标准答案完全一致）。

## 考前人脸采集（防止替考）

点击「开始答题」后会先弹出**人脸采集**，**必须完成才能进入考试**：

1. **现场拍摄**：只能用摄像头实时拍摄，不提供相册选图入口。
2. **活体检测**：拍摄前必须检测到明显的画面变化（略微转头），
   用来拦掉「拿一张静止照片对着摄像头」这种最简单的替考方式。
3. **随成绩存档**：照片（320×240 JPEG，约 10~20 KB）随成绩一起写入云端，
   教师端在「人脸」列点「查看」**按需拉取**（照片不进列表，不会拖慢看板）。
4. **人工核验**：教师端可对照照片确认是否为本人；活体未通过的会额外标注「活体未过」。

> ⚠️ **能力边界（重要）**：本功能**不做自动身份比对**。
> 浏览器端要自动判断「是不是本人」，必须有一张**参考照片**（学籍照）来比对，
> 而系统里没有学籍照片库。因此它的作用是：
> **现场留证 + 活体门槛 + 教师人工核验**，而不是「系统自动认出谁是谁」。
> 若要自动比对，需要先导入学籍照片（可作为后续开发项）。
>
> 另外，活体检测用的是「连续帧差异」这种轻量启发式，能拦住静止照片，
> 但**拦不住有人举着手机播放视频** —— 那需要更强的活体模型。

## 考场纪律与违规处理

进入考试前需阅读考试须知并勾选同意；点击「开始答题」后自动进入全屏，
并申请麦克风权限用于监测环境声音。

**电脑端与手机 / 平板端都受管控**，两套判定各用各的计时互不干扰：

| 违规类型 | 电脑端检测方式 | 手机 / 平板端检测方式 | 违规码 |
| --- | --- | --- | --- |
| 退出界面 | 切标签页、最小化、切到其他窗口（`visibilitychange` + `blur`） | 切到其他 App、退到后台、锁屏（`visibilitychange` + `pagehide`） | `leave` |
| 截屏 | 捕获 `PrintScreen` 按键；其他截图工具会因夺取焦点触发 `blur` | **系统截图无法被任何网页检测**，改用身份水印追溯 | `screenshot` |
| 分屏 | 退出全屏（`fullscreenchange`）+ 窗口宽度持续小于屏幕 85% | 可视高度持续不足屏幕高度的 **60%**（分屏、悬浮窗、小窗播放） | `split` |

> 两套分屏规则**按屏幕尺寸切换**（屏幕宽 < 1100px 走手机规则），**不用 UA 或触摸能力判断** ——
> `'ontouchstart' in window` 在很多桌面浏览器上也为真，用它判断会让桌面端的分屏检测直接失效。
| 复制粘贴 | `copy`/`cut`/`paste`、右键菜单、Ctrl/Cmd+C、V、X | 长按选中（`selectstart`、`contextmenu`）、长按粘贴 / 输入法粘贴（`beforeinput`） | `copy` |
| 声音 | 麦克风 + Web Audio 实时测声级，超过 **50 dB**（0~100 相对声级）并持续约 0.5 秒即触发。**只记录与提示，不立即交卷** | 同左（手机同样需要授权麦克风） | `sound` |

手机端另有两处专门处理：
- **输入法误报**：弹出输入法会压矮视口，与分屏特征相似。因此每次碰过输入框后 **2.5 秒内不判分屏**，
  且手机分屏判定只在**没有聚焦输入框**时累计计时。
- **长按菜单**：iOS 的「拷贝/查询」气泡不一定触发 `contextmenu`，因此额外用
  `-webkit-touch-callout: none` + `selectstart` + `beforeinput(insertFromPaste)` 三重覆盖。

**处理方式分三档**：

| 违规类型 | 第 1 次 | 第 2 次 | 说明 |
| --- | --- | --- | --- |
| 退出界面 | **警告** | **立即交卷** | 警告后给 3 秒宽限期，让学生有机会回到考试页 |
| 分屏 / 悬浮窗 | **警告** | **立即交卷** | 同上，3 秒宽限 |
| 环境声音超标 | **警告 + 记录** | 同左（不交卷） | 超过 50 dB 持续 1.5 秒触发；弹窗冷却 15 秒，避免连续弹 |
| 截屏（PrintScreen） | **立即交卷** | — | 电脑端键盘截屏 |
| 复制粘贴 | **立即交卷** | — | 电脑快捷键/右键菜单，手机长按选中/粘贴 |

- **警告弹窗**会写明「这是第几次、还剩几次机会、再犯将立即交卷」，点「我知道了」继续答题。
- **立即交卷**后：结果页醒目提示违规类型 → 成绩随记录实时上报云端 →
  教师端看板**报警区**列出该条违规、明细表该行**整行标红**并标注违规类型与发生时间。
- 声音超标**只警告不交卷**，但会记入成绩、交卷时上报，教师端同样标红并可看到实测分贝。

### 关于管控能力的边界（如实说明）

- **截屏**：电脑端可捕获 `PrintScreen` 按键与因截图工具夺取焦点产生的失焦，但**无法**检测不改变焦点的系统级截图。
  **手机 / 平板的系统截图（电源+音量键）完全无法被网页检测** —— 这是浏览器的能力边界，任何网站都做不到，
  因此**不对手机截图做任何检测**（此前尝试过的身份水印也已按需求移除）。
  若考场需要真正阻断截图，只能依靠监考老师或专用考试客户端。
- **分屏**：电脑端以「退出全屏」和「窗口宽度占屏幕比例」为准（屏幕宽度小于 1100px 不参与比例判定，避免小屏误报；
  不支持全屏 API 的浏览器自动跳过全屏判定）。**手机 / 平板没有可用的全屏 API，改看可视高度占屏幕高度的比例**：
  低于 60% 并持续 1.5 秒即判违规；输入法弹出、屏幕旋转后的 2.5 秒内不判定。
- **声音**：限值 **50 dB**，持续 **1.5 秒**才触发（避免咳嗽、关门等爆音误报）。
  浏览器测不到真实声压级（dB SPL 需要校准过的麦克风），
  因此界面统一用 **0~100 的相对声级**（等于 dBFS + 100）：
  0~20 数字静音 / 30~40 很安静的房间 / 40~50 安静 / 50~60 小声交谈 / 60~80 正常说话 / 85+ 大声。
  **限值 50 大致是「小声交谈的起点」**。
  采样使用 `getFloatTimeDomainData`（浮点）而非 8 位版本 —— 8 位量化下任何非静音信号的底噪就有 58，
  限值定得低会退化成「有声音就触发」。
  考试页的管控状态条会**实时显示当前声级与限值**，方便学生自查。
  需要考生授权麦克风，**未授权时不监测**，成绩单与教师端会如实标注「未监测」，且不因此判违规。
  阈值与持续时间写在 `assets/app.js` 的 `SOUND_DB_LIMIT` / `SOUND_HOLD`，按考场环境可自行调整。
- **超时不算违规**：倒计时归零属于正常自动交卷，记录标记为「超时交卷」，不标红、不报警。
- 考试开始后有 **1.5 秒缓冲期**，避免全屏切换瞬间的失焦被误判。

## 学生端功能

- **考生信息**：考核前必须填写**姓名、班级、学号**，校验通过才能进入答题（学号 4~24 位数字/字母）。
- **35 分钟倒计时**：顶部实时显示剩余时间；不足 10 分钟出现提醒条，不足 5 分钟转橙、不足 1 分钟转红闪烁；归零自动交卷。
- **自动判分**：交卷后立即给出最终得分、答对/答错/未作答统计、正确率与用时。
- **成绩自动上传**：交卷判分后自动把成绩写入云端，结果页实时显示上传状态。
  上传失败会在本机暂存并给出「重试上传」按钮，且下次打开页面时自动补传；**不影响得分与成绩单下载**。
- **分题库得分**：按来源题库拆分本次得分（抽题数 / 答对 / 答错 / 得分 + 合计行）。
- **错题回溯**：自动收集全部错题，完整展示题干、所有选项、考生答案与标准答案。
- **成绩单文档**：一键下载 A4 排版的 Word 成绩单（`.doc`），含考生信息、成绩汇总、
  考核状态（正常 / 违规 / 超时）与声音监测状态、分题库得分、全 50 题答题明细、签名栏。
- **历史考核记录**：每次交卷自动记录到浏览器本地（最多 200 条），带状态列，可导出汇总表（CSV）。
- **随机不重复**：每次进入或点击「重新抽题」都重新随机组卷，同一份试卷内不会出现重复题目。
- **键盘操作**：按 `A`~`H` 或 `1`~`8` 选择选项，`←` `→` 翻页。

## 教师端功能（`teacher.html`）

入口在学生端首页右下角的「教师端成绩汇总」。

- **口令门**：**每位教师使用各自的口令**登录，口令在服务端校验、**不出现在前端代码里**；
  看板右上角显示当前登录身份（教师一~教师四），验证通过后本机记住，可随时「锁定」切换他人。
  口令被轮换后，已记住的旧口令会在下次同步时被识别并退回登录页，不会静默显示成空表。
- **违规报警区**：有违规时页面顶部出现醒目报警区，按时间倒序列出违规类型、考生与发生时间。
- **统计卡**：参考人数、答卷份数、平均分、最高分、最低分、及格率、**违规记录数**、平均用时。
- **人脸核验**：明细表新增「人脸」列，显示「查看」/「未采集」/「活体未过」；
  点「查看」按需拉取该考生的考前照片（照片本体不随列表返回，避免看板变慢）。
- **成绩明细表**：序号、姓名、班级、学号、得分、答对、答错、未答、正确率、用时、交卷时间、**状态**、删除。
  违规行**整行标红**并标注违规类型与详情；超时交卷单独标注（不标红）；同一学号多次交卷标注「重考」并默认只保留最新一次。
- **删除与批量删除**：单条删除带二次确认；表格左侧可逐行勾选，勾选栏支持**一键全选当前筛选结果**（含半选态提示）。
  点「批量删除所选」会先弹出确认框写明**将删除多少条、删除后无法恢复**，
  确认后**每批 200 条**调用服务端批量删除函数（失败按 0.5s→1s→2s 退避重试），按钮上实时显示「删除中 x/y」进度。
- **清空全部成绩**：一键清空表内全部记录。确认框会列出**总条数与其中违规记录条数**，
  并要求**手动输入「清空全部」**才能点确认 —— 输入不对时确认键保持禁用。
- **筛选与排序**：按班级筛选、按姓名/学号模糊搜索、**只看违规记录**；按交卷时间、得分、班级排序。
- **导出与打印**：导出当前筛选范围的成绩册 CSV（含状态与违规详情列），或打印 / 导出 PDF。
- **自动刷新**：每 15 秒自动同步一次（有违规报警时更需及时），也可手动刷新。

## 并发容量（1000 人同时在线）

这套系统的服务器只在**两个时刻**被触碰，其余时间完全空闲（没有轮询、没有长连接）：

| 时刻 | 请求量 | 单人开销 |
| --- | --- | --- |
| 打开考试页 | 5 个静态文件 | 约 **264 KB**（index.html + style.css + app.js + banks.js + 云 SDK） |
| 交卷 | **1 次**云端写入 | 约 300 B |

**实测结果**（`load-test.js`，2026-10-16）：

| 场景 | 结果 |
| --- | --- |
| 1000 次打开页面（并发 20） | **全部成功**，p50 134 ms |
| 1000 条成绩写入（并发 50） | **全部成功**，耗时 3.8 s，约 **264 条/秒**，p95 325 ms |
| 1000 条成绩写入（并发 15） | **全部成功**，耗时 11.7 s，约 85 条/秒，p95 235 ms |

结论：按正常节奏（1000 人在几十秒内陆续进入、陆续交卷），**1000 人同时在线完全够用**，
写入能力有数倍余量。

### ⚠️ 已知边界：平台级限流

把 **1000 条写入压在同一个瞬间**（并发 300）时，平台会直接返回
「系统维护中 / 当前负载过高，请稍后再试」的限流页 —— **连静态资源请求也会被一起挡掉**。
这是托管平台的自我保护，不是应用能调优掉的参数。

因此做了两层客户端加固：

1. **上传随机错峰**：交卷后不是立刻写入，而是先随机等一小段（手动交卷最多 1.2 秒、
   违规上报 0.8 秒、超时自动交卷最多 8 秒），把集中写入摊开。
   错峰只影响网络写入的时机，**不影响判分时刻与成绩内容**。
2. **自动退避重试**：写入失败（网络抖动、平台限流）时按 0.8s → 1.6s → 3.2s 自动重试 3 次，
   全部失败才退回「重试上传」按钮，并把成绩暂存在本机、下次打开自动补传。

### 实操建议

- **分批进场**：让各班错开几分钟进入考场，避免 1000 人同一分钟集中拉取 264 KB。
- **不要统一卡点交卷**：若规定「同一时刻交卷」，会正好踩在平台限流线上；
  建议允许在最后 5 分钟内自行交卷（应用已有超时错峰兜底）。
- **静态资源未压缩**：当前托管未开启 gzip，264 KB 是原始体积。
  若日后换到支持压缩的托管，这一项会降到约 90 KB。

## 成绩汇总架构

```
考生设备                云数据库（托管 PostgreSQL）            教师设备
┌──────────┐          ┌────────────────────────┐          ┌──────────┐
│ index.html│───写入──▶│ exam_records           │◀──口令读取─│teacher.js│
│  交卷判分 │  INSERT  │  · 仅开放 INSERT 策略    │   RPC     │  看板    │
│ 违规即上报 │  +校验   │  · 无 SELECT 授权        │          └──────────┘
└──────────┘          └────────────────────────┘
```

- 学生端只被授予 **INSERT** 权限，写入策略带取值范围校验（分数 0~100、各项计数 0~40、
  违规码限定在 `leave / screenshot / split / copy / sound` 白名单内），**任何人都无法直接读取成绩表**。
- 教师端口令门、读取、单条删除、批量删除、清空全部分别走服务端函数
  `teacher_login(p_key)` / `teacher_exam_records(p_key)` / `teacher_delete_record(p_key, p_id)` /
  `teacher_delete_records(p_key, p_ids uuid[])` / `teacher_clear_records(p_key)` / `teacher_record_photo(p_key, p_id)`；
  全部是 `SECURITY DEFINER`，在 SQL 内部校验口令，后四个复用 `teacher_login` 判定身份。
  **口令只写在服务端函数里，前端代码不含任何口令**。
- 批量删除是**一次调用删一批**（客户端每批 200 个 id），而不是逐条发请求 —— 既快，也避免把平台压到限流。
- 前端只携带 `publicConfig` 中的 `endpoint` / `oauthRelayBaseUrl` / `publishableKey`。

> ⚠️ 为便于部署，`assets/workbuddy-cloud-sdk.js` 是云服务 SDK 的自带副本
> （`@tencent-ai/workbuddy-cloud-sdk@0.1.3-dev.05a12d5`，npm `dev` 通道的 IIFE 构建），
> 页面运行时不依赖任何外部 CDN。

## 运行方式

**方式一：线上使用**（推荐，成绩可汇总）

学生打开站点答题，教师打开 `teacher.html` 查看汇总。
云服务按发布域名做 Origin 校验，因此**必须通过发布域名访问**才能写入云端。

**方式二：本地运行**

```bash
python -m http.server 8080
# 浏览器访问 http://localhost:8080
```

本地运行时会因 Origin 不匹配而无法写入云端，但**答题、判分、倒计时、考场管控、错题回溯、成绩单下载全部照常可用**。

## 题库更新方式

**选择题库**（三份 docx）：

```bash
python tools/build_banks.py 军事题库.docx 学生手册题库.docx 安全知识题库.docx
```

`build_banks.py` 处理了真实题库的排版问题：选项与题号粘连（`D.10` + `59.` → `D.1059.`）、
小数选项粘连（`D.1.8` + `75.` → `D.1.875.`）、答案标记写在题干中间、小节标题混入选项末尾等。

**填空题库**（`自编题(1).doc`）：

```bash
python tools/extract_doc.py 自编题.docx tools/parsed/zibian.txt   # 需要时先看原文
python tools/build_fill_bank.py
```

- 原文档把**填空答案用加粗标出**，`build_fill_bank.py` 里逐题记录了题干、空格答案与判分接受写法，
  修改后重新运行即可生成 `assets/banks_fill.js`。
- `tools/extract_doc.py` 直接解析 Word 97-2003 二进制格式（OLE2 + 分片表），只依赖 `olefile`。
  注意 `.doc` 的 `fcMin/fcMac` 是失效的遗留字段，正文必须以分片表为准。

## 运维备注

- **口令轮换**：四个教师口令都定义在服务端函数 `teacher_login` 的 VALUES 列表里，
  单独替换其中任意一个只影响该教师、其余三人不受影响，旧口令立即失效。
- **口令分发**：建议每位教师只持有自己的口令，离岗或轮换时单独作废，便于追责。
- **判分在前端完成**：云端只保存考生上报的结果，不做二次判分；写入策略会校验取值范围拦截明显异常的数据。
- **违规申诉**：违规判定含启发式规则（如分屏比例、声音阈值），教师端提供违规详情与发生时间，
  建议对疑似误报的记录人工复核后再处理。
- 表内数据可用教师端看板逐条删除，或在云服务控制台按需清理。

> ⚠️ `cloud-e2e.js` 的最后一段会**真实清空成绩表**（用于验证「清空全部」函数）。
> 它内置了安全护栏：**只有确认表内全部是本次测试造的数据时才会执行**，否则跳过该用例并退出。
